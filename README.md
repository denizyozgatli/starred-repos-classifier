# GitHub Starred Repositories Classifier

A fast, responsive, minimal, and open-source web catalog and standalone CLI to automatically fetch, classify, and filter GitHub starred repositories with hybrid deterministic rules and Gemini LLM.

**Live Demo Site:** [https://denizyozgatli.github.io/starred-repos-classifier/](https://denizyozgatli.github.io/starred-repos-classifier/)

The project is completely general-purpose: anyone can use it with their own GitHub starred repositories. It runs entirely as a client-side static application with no runtime backend, database, or external service dependencies.

## Standalone CLI (`star-classifier`)

The project includes an npm-distributed standalone CLI that fetches and classifies any user's GitHub stars into a structured JSON dataset ready for the web dashboard.

### Quick Start with `npx`

```bash
# Fetch and classify public starred repositories for any GitHub username:
npx star-classifier --user octocat

# Or using the package name:
npx starred-repos-classifier --user octocat
```

### Global Installation (Optional)

```bash
npm install -g starred-repos-classifier

# Run directly:
star-classifier --user torvalds -o torvalds-stars.json --rule-only
```

### Options & Flag Reference

| Option | Shorthand | Description | Default |
|---|---|---|---|
| `--user <username>` | `-u` | Target GitHub username to fetch stars for | Authenticated user |
| `--token <token>` | `-t` | GitHub Personal Access Token (or `GITHUB_TOKEN` env var) | None |
| `--output <path>` | `-o` | Output file destination path | `./repos.json` |
| `--rule-only` | | Use deterministic rules only (skips all LLM calls) | `false` |
| `--gemini-key <key>` | | Google Gemini API key for fallback classification (or `GEMINI_API_KEY`) | None |
| `--cache <path>` | | Path to isolated local classification cache file | `./.star-classifier-cache.json` |
| `--no-cache` | | Disable reading and saving the classification cache | `false` |
| `--help` | `-h` | Display help banner with usage examples | |
| `--version` | `-v` | Display version number (`1.0.0`) | |

### Ingestion & Authentication Modes

#### Mode 1: Public Username Mode (Unauthenticated)
```bash
npx star-classifier --user <github-username>
```
- Fetches all public starred repositories for the specified user via GitHub's public REST API.
- No GitHub account or token required.
- Subject to GitHub's standard unauthenticated rate limit (60 requests/hour).
- Star Lists are gracefully omitted (`lists: []`) since GitHub Star Lists require GraphQL authentication.

#### Mode 2: Authenticated User Mode (Full Features & Star Lists)
```bash
npx star-classifier --token ghp_yourPersonalAccessToken
# or:
GITHUB_TOKEN=ghp_yourToken npx star-classifier
```
- Automatically resolves your authenticated GitHub account via `GET /user`.
- Fetches all your starred repositories via `GET /user/starred`.
- Raises GitHub API rate limits to **5,000 requests/hour**.
- Fetches private and public **GitHub Star Lists** via GraphQL API and tags repositories with their list memberships.

### Privacy & Data Ownership

> **Your GitHub token and generated dataset stay in your own environment.**

- **Zero Central Infrastructure**: This project is 100% open source and local/self-hosted. There is no central server, backend API, database, user tracking, or telemetry.
- **Local File Output**: The CLI saves your generated dataset directly to your local machine (default: `./repos.json`).
- **In-Memory Web Application**: When you click "Import JSON" in the web application, the dataset is parsed and held strictly in your browser session's memory. No repository data is ever uploaded or transmitted to any server.
- **Credential Safety**: `GITHUB_TOKEN` and `GEMINI_API_KEY` are read only from your local CLI flags or `.env` and used exclusively to communicate directly with GitHub's and Google's APIs from your computer. Secrets are never saved to datasets, caches, or build artifacts.

### Classification Strategy & Gemini Fallback

1. **Deterministic Rules (Default & Fast)**: Repositories are categorized using rule sets matching repository names, normalized topics, primary language, and keywords in descriptions.
2. **Offline Mode (`--rule-only`)**: If you prefer zero network calls outside GitHub, pass `--rule-only`. Ambiguous or sparse repositories are categorized as `"Other"`.
3. **AI Fallback (Gemini)**: If you provide a Gemini API key (`--gemini-key <key>` or `GEMINI_API_KEY`), ambiguous repositories are classified using `gemini-3.8-flash`. Outgoing requests are rate-limited to 12.5 seconds to respect free-tier quotas.

The generated dataset is a standard JSON file directly loadable by the web application.

The application accepts both representations:

   An array of repository objects:
   ```json

     {
       "id": 10270250,
       "name": "react",
       "fullName": "facebook/react",
       "owner": "facebook",
       "description": "The library for web and native user interfaces.",
       "topics": ["declarative", "frontend", "javascript", "react", "ui"],
       "language": "JavaScript",
       "stars": 230000,
       "url": "https://github.com/facebook/react",
       "updatedAt": "2026-09-26T12:00:00Z",
       "category": "Web Frontend",
       "lists": ["Frontend Stack"],
       "classification": {
         "method": "rule",
         "confidence": 0.95,
         "classifiedAt": "2026-09-26T12:00:00Z",

     "username": "octocat",
     "source": { "type": "github-stars", "username": "octocat" },
     "repos": [ ... ]
   }
   ```

## Features

- **Automated Repository Classification**: Classifies starred repositories using deterministic rules based on language, topics, name, and description, falling back to Gemini for ambiguous metadata.
- **GitHub Star Lists Support**: Fetches user-curated Star Lists via GitHub's GraphQL API. Repositories display GitHub-styled purple list badges and can be filtered by specific lists, seamlessly combining with category and language filters.
- **Fast Client-Side Search (<100ms)**: Real-time fuzzy searching across repository names, owners, descriptions, topics, and languages via Fuse.js.
- **Search Usability**: Accessible `/` keyboard shortcut to focus search, a custom clear button, and suppression of duplicate browser-native search cancel controls.
- **Faceted Category & Star List Filtering**: 10 primary categories and dynamic Star List pills with live repository counts, supporting horizontal scrolling on mobile.
- **Language Filtering**: Dynamically populated from active repositories with counts and an expandable `+N more` selector.
- **Sorting Options**: Sort by relevance, most stars, recently updated, or alphabetically (A–Z) using a custom accessible listbox styled to match GitHub's dark aesthetic.
- **Deep-Link URL State**: URL search parameters (`q`, `category`, `language`, `list`, `sort`) synchronize bidirectionally, making every search and filter view shareable and bookmarkable.
- **Client-Side Data Export**: Export active filtered views or complete datasets directly to JSON (100% re-importable), CSV (RFC 4180 compliant with UTF-8 BOM for Excel), or Markdown with zero server interaction.
- **Responsive Layout**: Clean desktop grid with mobile-optimized touch controls and zero horizontal overflow across all screen sizes.
- **Full-Card Navigation**: Entire card surfaces are clickable directly to GitHub repositories, complete with GitHub language color indicators and topic badges.

## Architecture

```
GitHub API (GET /users/{username}/starred OR GET /user/starred)
       │
       ▼
Fetch & Normalization (bin/cli.ts / scripts/fetch.ts)
       │
       ▼
Classification Cache Check (.star-classifier-cache.json)
       │
       ▼
Deterministic Rule Classifier (scripts/lib/classifier.ts)
       │
       ├─► Confident match ──► Cached (rule)
       │
       ▼ (if ambiguous or sparse)
Gemini LLM Fallback (gemini-3.8-flash, ~4.8 RPM rate-limited)
       │
       ├─► Successful response ──► Cached (llm)
       └─► Quota limit / 429 / 503 / No key ──► "Other" (fallback, NOT cached)
       │
       ▼
Strict Schema Validation (scripts/lib/validator.ts)
       │
       ▼
User's Local repos.json (output destination, e.g. ./repos.json)
       │
       ▼
React 19 + Vite Static Dashboard (Loaded via "Import JSON" into browser memory)
```

### Data & Cache Design

- **User-Owned Data**: The web application never connects directly to GitHub or Gemini; it receives datasets through the user's manual "Import JSON" action and retains them strictly in browser memory.
- **Local Isolation**: The CLI writes output directly to your local file path (default: `./repos.json`).
- **Isolated Classification Cache**: Classification results are cached locally in `./.star-classifier-cache.json` to prevent re-querying the Gemini LLM for unchanged repositories.
- **Transient Fallbacks**: If Gemini returns a rate-limit (429) or unavailable (503) error, the repository is assigned `category: "Other"` with `method: "fallback"`. Fallback results are **never** persisted to cache, ensuring they remain eligible for re-classification on future pipeline runs.
- **GitHub Star Lists (GraphQL)**: Curated star list memberships are fetched via GitHub's GraphQL API when an authenticated token (`GITHUB_TOKEN`) is provided. If running unauthenticated against public stars, Star Lists retrieval is gracefully skipped (`lists: []`) without breaking the ingestion pipeline.

## Classification

Every repository is classified into exactly one primary category from the allowed vocabulary.

### Classification Order

1. **Manual Overrides**: Optional entries in `overrides.json` take highest precedence when configured (`method: "manual"`, confidence `1.0`).
2. **Local Cache Match**: If repository metadata matches a valid non-fallback classification in `.star-classifier-cache.json` by SHA-256 `inputHash`, the classification is reused.
3. **Deterministic Rules**: Tokenizes repository name, matches normalized topics, checks primary language, and inspects descriptions. If a rule reaches the confidence threshold, it classifies the repository (`method: "rule"`, confidence `0.85`–`0.95`).
4. **Gemini Fallback**: Ambiguous or sparse repositories are passed to Gemini (`method: "llm"`, model `gemini-3.8-flash`).
5. **Safe Fallback**: If the Gemini API is unreachable, unconfigured, or rate-limited, the repository is categorized as `"Other"` with `method: "fallback"` (confidence `0.5`).

## Development Guidelines

- **Isolate Changes**: Keep frontend UI updates separate from data pipeline and classifier changes.
- **Protect Secrets**: Never commit `.env` or hardcode API tokens into repository files.
- **Benchmark Integrity**: Do not alter `data/benchmark.json` or `data/unseen-test.json` to artificially inflate accuracy scores.
- **Cache Invariants**: Never persist fallback classifications (`method: "fallback"`) to the persistent cache.
- **Pre-Commit Verification**: Always run `npm test` and `npm run build` before committing changes.
- **Keep Docs Synchronized**: Update `README.md` whenever operational steps, dependencies, or architectural rules change.
